# 大会情報バックエンド（Googleスプレッドシート）セットアップ手順

`Code.gs` を Google Apps Script の Web アプリとして公開するための、最初の1回だけ必要な設定手順です。
（この作業はGoogleアカウントの操作を伴うため、担当者が実際にブラウザで行う必要があります）

## 1. 新しいGoogleスプレッドシートを作る

1. `ishikawaboundtennis@gmail.com` でログインした状態で [sheets.google.com](https://sheets.google.com) を開く
2. 「空白のスプレッドシート」を新規作成
3. わかりやすいタイトルに変更する（例：「バウンドテニス協会HP_大会データ」）

## 2. Apps Script を貼り付ける

1. メニューの「拡張機能」→「Apps Script」を開く
2. 開いたエディタに元々ある `function myFunction() {...}` を全部消す
3. このフォルダの `Code.gs` の中身を全部コピーして貼り付ける
4. 上部の「プロジェクト名」を「大会データAPI」などに変更
5. フロッピーアイコン（保存）をクリック

## 3. 初期設定用の関数を1回だけ実行する（ヘッダー行の作成）

1. エディタ上部の関数選択ドロップダウンで `setup` を選ぶ
2. 「実行」ボタンを押す
3. 「承認が必要です」と出たら「権限を確認」→ 自分のGoogleアカウントを選択 →
   「詳細」→「（プロジェクト名）に移動（安全ではないページ）」→「許可」
   - ※これは自分たちで作ったスクリプトなので問題ありません。Googleの標準的な確認画面です。
4. 実行が完了したら、スプレッドシートに戻り「events」という名前のシートが増えていて、
   1行目にヘッダー（id, date, dateEnd, ...）が入っていることを確認する

## 4. Web アプリとしてデプロイする

1. エディタ右上の「デプロイ」→「新しいデプロイ」をクリック
2. 歯車アイコン（種類の選択）→「ウェブアプリ」を選ぶ
3. 以下のように設定する

   | 項目 | 設定値 |
   |------|--------|
   | 説明 | 大会データAPI v1 |
   | 次のユーザーとして実行 | 自分 |
   | アクセスできるユーザー | 全員 |

4. 「デプロイ」ボタンを押す
5. 再度Googleの承認画面が出た場合は手順3と同様に許可する
6. 完了すると「ウェブアプリのURL」が表示されるので、**このURLをコピーする**
   （`https://script.google.com/macros/s/...../exec` という形式）

## 5. コピーしたURLを教えてください

このURLを Claude に伝えてください。`index.html` 内の `SHEETS_API_URL` にこのURLを設定し、
管理画面の保存先がこのスプレッドシートになるように反映します。

## 6. Googleサインインの設定（管理画面へのログインに使う「鍵」の発行）

管理画面へのログインをパスワードではなく、協会のGoogleアカウントで行うようにするための設定です。
Google Cloud Console でしか発行できないため、担当者が実際にブラウザで行う必要があります。

1. `ishikawaboundtennis@gmail.com` でログインした状態で [console.cloud.google.com](https://console.cloud.google.com) を開く
2. 上部の「プロジェクトを選択」→「新しいプロジェクト」→ 名前を「ibta-hp」などにして作成
3. 左メニュー「APIとサービス」→「OAuth同意画面」
   - User Type: 「外部」を選択→作成
   - アプリ名: 「石川県バウンドテニス協会 管理画面」、サポートメール・デベロッパー連絡先: `ishikawaboundtennis@gmail.com`
   - スコープ画面はそのまま「保存して次へ」
   - テストユーザーの画面で「+ ADD USERS」→ `ishikawaboundtennis@gmail.com` を追加
   - 公開設定は「テスト」のままでOK（Googleの審査は不要）
4. 左メニュー「認証情報」→「+ 認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: 「ウェブ アプリケーション」
   - 名前: 「ibta-hp admin」など
   - 「承認済みのJavaScript生成元」に、実際に公開するホームページのURL
     `https://ishikawa-boundtennis.github.io` を追加
   - 「作成」をクリック
5. 表示される「クライアントID」（`〇〇〇.apps.googleusercontent.com` の形式）をコピーする
   - これはパスワードと違って公開しても問題ない値です
6. このクライアントIDを Claude に伝えてください。`index.html` の `GOOGLE_CLIENT_ID` と
   `Code.gs` の `GOOGLE_CLIENT_ID` の両方に同じ値を設定します
7. `Code.gs` 側の `ALLOWED_EMAILS` に、管理画面へのログインを許可するGoogleアカウントの
   メールアドレスを追加・変更できます（担当者が増えた場合はここに追記）

## 補足：コードを更新したとき

将来 `Code.gs` の中身を修正した場合、貼り付け直すだけでは反映されません。
「デプロイ」→「デプロイを管理」→ 該当のデプロイの鉛筆アイコン →
「バージョン」を「新バージョン」に変更 →「デプロイ」を押す必要があります
（URLは変わりません）。

## 補足：大会写真フォルダの機能を有効にする（Googleドライブの承認が1回だけ必要）

大会写真を「フォルダごと表示する」機能（`?type=photos`）は、スクリプトが
**Googleドライブのフォルダの中身を読む**ため、**追加の承認が1回だけ必要**です。
`Code.gs` を貼り替えただけでは動かず、写真が1枚も表示されません。

1. `Code.gs` を最新の内容に貼り替えて保存する
2. エディタ上部の関数選択ドロップダウンで `setup` を選び、「実行」を押す
3. 「承認が必要です」と出るので、**「権限を確認」→ アカウントを選択 →「詳細」→
   「（プロジェクト名）に移動（安全ではないページ）」→「許可」**
   - 今回は「Googleドライブのファイルの表示」という項目が増えています。これを許可してください
   - この承認をしないと、写真の一覧だけがずっと空のままになります
4. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン」を「新バージョン」→「デプロイ」

**動作確認:** ブラウザで次のURLを開き、`{"ok":true,...}` と写真の一覧が返ってくればOKです。

```
（ウェブアプリのURL）?type=photos&folder=（写真フォルダのID）
```

- `folder=` にはフォルダの共有URLをそのまま貼っても構いません
- `{"ok":false,"error":"folder_not_shared"}` と返る場合は、
  そのフォルダの共有が「リンクを知っている全員」になっていません
- `{"ok":false,"error":"folder_not_found"}` の場合は、フォルダIDが違うか、
  協会アカウントからそのフォルダが見えていません

> 共有されていないフォルダは、中身を返さない作りにしてあります。
> スクリプトは協会アカウントの権限で動くため、共有していないフォルダも技術的には読めてしまいます。
> 公開する意図のないフォルダのファイル名が外に出ないよう、入口で止めています。

## 補足：大会写真の自動縮小を有効にする

大会写真フォルダに入れられた写真を、**サイトの表示に必要な大きさ（幅1600px）まで
自動で縮小して置き換える**機能です。カメラの写真は1枚2〜3MBありますが、
縮小すると1枚300〜500KB程度になります。1大会200枚で約500MB→約80MBです。

**なぜ必要か:** 無料のGoogleアカウントの容量15GBは、ドライブだけでなく
**Gmailとも共有**しています。原寸のまま貯めると数年で埋まり、
**大会写真だけでなく協会のメールも受信できなくなります**。

### 先に決めておくこと（重要）

この機能は、縮小版に置き換えたあと**元の写真をゴミ箱へ送ります**。
原寸の写真はドライブに残りません。

- **原本が必要なら、アップロードする前に事務局のパソコンや外付けHDDに保管してください。**
  ドライブ側は「公開用の縮小版の置き場」と割り切る形になります
- ゴミ箱の中身は**30日間は容量を使い続けます**。すぐに空き容量を増やしたい場合は、
  ドライブのゴミ箱を手動で空にしてください（30日経てば自動で消えます）
- 縮小の画質はGoogle任せです。サイトの表示には十分ですが、**印刷用途には向きません**

### 設定手順（1回だけ）

1. `Code.gs` を最新の内容に貼り替えて保存する
2. エディタ上部の関数選択ドロップダウンで **`setupPhotoResizeTrigger`** を選び、「実行」を押す
3. 承認を求められたら許可する（写真の差し替えを行うため、ドライブへの書き込みの承認が要ります）
4. 実行ログに「大会写真の自動縮小を1時間おきに実行するよう設定しました。」と出れば完了

これ以降、**1時間おきに自動で縮小**されます。職員の操作は「フォルダに写真を入れる」だけで、
今までと変わりません。

### 動くのを確かめる

関数選択で **`resizeTournamentPhotos`** を選んで「実行」すると、その場で1回動きます。
実行ログに `大会写真の縮小: 縮小○枚 / 対象外○枚 / 失敗○枚` と出ます。

- **`失敗` が出るのは正常な場合があります。** アップロード直後はドライブ側の縮小版が
  まだできていないため、その回は飛ばして次回に回します。1時間後にもう一度実行されます
- `対象外` は、もともと小さい写真（700KB未満）・画像以外のファイル・処理済みの写真です

### 仕様のメモ

- **大会データの「写真フォルダURL」欄に登録されているフォルダだけ**を対象にします。
  登録していないフォルダの写真には一切触れません
- 処理済みの写真には、ファイルの**説明欄**に `[web用に縮小済み]` という目印が入ります。
  ファイル名は変わりません（元がPNGの場合のみ拡張子が `.jpg` になります）
- 1回の実行で最大40枚、4分までで打ち切り、残りは次回に回します
  （Apps Scriptは1回6分で強制終了されるため）
- 縮小しても小さくならない写真は、置き換えずに目印だけ付けて次回から飛ばします
- 差し替えた直後の最大10分間は、サイト側のキャッシュが古いままで
  写真が一時的に表示されないことがあります（`PHOTO_CACHE_SEC`）
